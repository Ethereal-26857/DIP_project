## chat3

Q:

```python
F = np.fft.fft2(img)
H_i = ideal_lpf(img.shape, D0=30)
out = np.real(np.fft.ifft2(F * H_i))
```

**滤波结果花掉，哪里有问题？**

A:

1. `ideal_lpf` 里的 `distance_grid` 是以**图像几何中心**为圆心算距离 \(D(u,v)\) 的，因此 \(H_i\) 的“通带圆”中心在**谱的中心**。
2. 但裸的 `np.fft.fft2(img)` 把**零频放在左上角**（规范 DFT 布局），谱的能量与坐标轴之间没有和 \(H_i\) 对齐。
3. 二者逐元素相乘时，等于用**移过位的掩膜**去挡**没移过的谱**（或反之），结果不一定是 NaN，但空域会严重错位、看起来像斜纹或涂抹，这就是 debug 里最“阴间”的那类** silent bug**。

按 `final` 约定成套写：`F = fft2c(img)` 把零频挪到中心，再乘 \(H\)，逆变换用 `ifft2c` 把布局恢复，保证 **\(H\) 与 \(F\) 同一套“中心化”布局**。

```python
F = fft2c(img)
out_i = normalize01(ifft2c(F * H_i))
```

若坚持不用 `fftshift`，就必须把 \(H_i\) 改写成与角点零频配套的形式（一般不推荐给作业手写），不如统一用 `fft2c` / `ifft2c`。

## chat4

Q:

```python
def ideal_lpf(shape, D0):
    D = distance_grid(shape)
    return (D <= D0).astype(np.float64)
```

**和 Butterworth / Gaussian 比，为什么就它振铃最重？代码上对应哪一点？**

A:

`(D <= D0)` 一行就是**理想值在圆内外从 1 跳到 0**：频域上是一个**不连续**的圆盘指示函数。根据傅里叶对偶，频域越“陡”、空域冲激响应拖尾越长，在强边缘附近就会产生 **Gibbs 现象**——肉眼就是 skull 边缘一圈圈 ripple。Butterworth 在截止处是 \(1/(1+(D/D_0)^{2n})\)，Gaussian 是 \(\exp(-D^2/\cdots)\)，两者在截止带都是**连续甚至光滑**下降的，空域核更像有限支撑的高斯型，振铃就轻得多。

写报告时不必改这三行实现；重点是能指着 `(D <= D0)` 说明：**阶跃截止 → 强振铃；平滑截止 → 弱振铃**。这也是 Project 1 “Ringing Effect” 题目的标准答案方向。

```python
def gaussian_kernel(ksize, sigma):
```

Q:

```python
def psf2otf_wrong(psf, shape):
    out = np.zeros(shape, dtype=np.float64)
    out[: psf.shape[0], : psf.shape[1]] = psf
```

**和 `convolve2d` 对不上，缺了哪一步？**

A:

可以把 `psf2otf` 想成：先把小核放进大图左上角，再**把核中心“搬到” FFT 对应零频的那一格**。`np.fft.fft2` 假设序列从 \((0,0)\) 起算，循环卷积的零频对齐方式与“核中心在几何中心”的物理直觉不一致；没有 `np.roll` 时，等价于认为核的锚点在**角上**，和 `signal.convolve2d` 在频域实现的**循环移位约定**错位，OTF 相位错一截，逆变换回去就和空域卷积对不齐。

```python
out = np.roll(out, -kh // 2, axis=0)
out = np.roll(out, -kw // 2, axis=1)
```

与 `convolve2d(..., boundary='symm')` 仍可能有**边界差异**（对称延拓 vs 纯周期），所以对比误差要看**图像中部 ROI**，别死磕最外一圈像素。

## chat17

Q:

```python
mse = np.mean((normalize01(img) - normalize01(out)) ** 2)
```

**我想算和原图的 MSE，这样写**哪里有问题？**

A:

⚠️ `normalize01` 对 `img`、`out` **各自**做 min-max 拉伸到 \([0,1]\)。若两幅图整体亮度差一截，各自拉伸后会把差距“吃掉”，MSE 变小，**不再反映原始灰度空间里的误差**；若想做 PSNR，更不能对二者分别拉伸。

应在**同一套线性标度**上比较：例如读入后只做一次全局归一，或二者已在 \([0,1]\) 且未二次 per-image 拉伸，就直接：

```python
mse = np.mean((img - out) ** 2)
```

若 `out` 是滤波后未裁剪的 `float`，要和 `img` 对齐 dtype 与范围再算；报告里写清“在哪个动态范围上定义 MSE”。

1. **先看 `log|F|`**：外围是否还有亮尖峰没进 `peaks`——有则**加 K**（多挖几对谐波），或检查 `suppress` 是否太大，把相邻真峰抹没了导致漏检。  
2. **峰位对、mask 太窄**：尖峰像个“小钻石”，圆半径 `r` 盖不全，就**略增 r**（例如 8→9→10），看条纹是否干净。  
3. **脑组织边沿发糊、纹理被咬平**：往往是 `r` 过大或误把组织高频当噪声挖了，应**减 r**、或重新看 `peaks` 是否点在解剖结构对应的合理高频上。

调参最忌三件事一起乱拧；建议固定 `suppress`，每次只动 `K` 或 `r` 之一，并打印：

```python
print("peaks:", peaks)
```

与频谱图对照，形成可追溯的调试记录，也方便写进实验报告“参数选择依据”。

## chat19

Q:

```python
Fn = fft2c(noisy_img)
out = normalize01(ifft2c(Fn * H))
```

**`H` 里有 0，逆变换后 `out` 里出现轻微虚部警告 / 数值噪点，**正常吗？哪里要改？**

A:

**正常数值现象。** 陷波遮零在数学上就是把某些频率完全删掉，IFFT 后理论仍应为实值，但浮点累加会在虚部留下 \(10^{-15}\) 量级垃圾；若你手写 `np.fft.ifft2` 且忘了取实部，Jupyter 有时会甩 `ComplexWarning`。`final` 的 `ifft2c` 已经统一 `np.real`，相当于把数值噪声砍掉。

若虚部大到 `1e-3` 量级，才要怀疑是否 **shift/ifftshift** 配对错了、或 `H` 不满足共轭对称导致本应实值的输出被破坏。那种情况下问题不在 `np.real`，而在掩膜构造。

## chat20

Q:

```python
sigma_list = [1, 3, 5]
for s in sigma_list:
    K = gaussian_kernel(ksize, s)
```

**这里 `NameError: name 'ksize' is not defined`，**哪里有问题？**

A:

`ksize` 不是全局常量，必须**由当前 \(\sigma\)** 决定：高斯核在 \(3\sigma\) 之外几乎可忽略，故常用 `ksize = 2*ceil(3*s)+1` 保证奇数长度且覆盖有效支撑。写在 `for` 外却忘赋值，或上一行拼写错了变量名，都会触发本 `NameError`。

与 `final` 对齐的写法：

```python
for s in sigma_list:
    ksize = int(2 * np.ceil(3 * s) + 1)
    K = gaussian_kernel(ksize, s)
```

`int` 与 `np.ceil` 配合是为避免 `float` 下标；若 \(\sigma\) 很小，`ksize` 至少仍是 3，不会是退化核。
